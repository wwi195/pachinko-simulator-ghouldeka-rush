# グール超デカ RUSH演出特化版 設計書

## コンセプト
`pachinko-simulator-ghouldeka`（電サポ5回リセット＋上乗せ方式）をベースに、`pachinko-simulator-ghoul-rush`と同じ「通常時はスキップし、RUSH中の演出だけを繰り返し楽しむ」フォーマットを適用する。ghouldekaには保留キューの概念がないため、専用の新方式（貯める→ポケット投入→変動）を採用する。

## アーキテクチャ
`pachinko-simulator-ghoul-rush`と同じ3分割構成。
- `logic.js` — 通常時確率（ghouldeka現行仕様を移植）＋RUSH構造（新方式）の純粋ロジック
- `rush-view-engine.js` — 投資額シミュレーション、演出モード定義、リーチ数字重み、月山絶叫用の色重み
- `script.js` / `index.html` / `style.css` — 画面・演出

## 通常時（投資額シミュレーション、ghouldeka現行仕様のまま）
- P_ZUGAR = 1/999.9、P_CHARGE = 1/538.3、P_FALSE_ENZOKU = P_ZUGAR×(0.3/0.7)
- スピンコスト固定 30回転/千円（ghouldekaに回転数レート選択肢はないため、選択UIなし）
- チャージ：+280球、RUSHには繋がらない（ループ継続）
- 図柄ぞろい：50%で「7500 PREMIUM」+7000球→RUSH突入、50%で「3000」+2800球→通常のまま継続

## RUSH構造（新方式）
- 電サポ残り初期値5、当たったら5にリセット、外れが続き残り0でRUSH終了
- 電サポ抽選確率：1/7.7（ghouldeka現行と同じ）
- 当たり時：**3000ボーナス確定(+2800球)、そのうえで自動連結の50%上乗せ連鎖**（成功する限り3000刻みで加算、失敗した時点で確定）。6000/3000の分岐は廃止。
- 「終了する」スキップボタンは設置しない（手動トリガー式のため）

## 変動（貯めるボタン1回分のシーケンス）
「貯める」押下 → ①ポケット投入演出 → ②スピン開始 → ③あおり（リーチ確定前の煽り）→ 分岐：
- リーチ確定（当たりは常に、外れは50%=ガセリーチ）：④リーチ突入 → はさみテンパイ保持(約3秒、ghoul-rush同様) → ⑤結果
- リーチなし外れ（外れの残り50%）：そのまま約1.5秒の外れ変動 → 結果

ghoul-rushのLCD 3桁演出（`runLcdSequence`相当）を流用し、テンパイ数字（1〜8、7=100%/3=90%信頼度、他は均等）による体感信頼度演出もそのまま踏襲する。ただし数字重みの元になる`P_RUSH`・ガセリーチ発生率は本プロジェクトの値（1/7.7、外れの50%固定）に合わせて再計算する。

当たり時の自動連結上乗せ連鎖は、LCD演出を都度は通さず「3000確定→上乗せ判定→(成功)6000→上乗せ判定→…→(失敗)確定」という簡易な連続表示（ghouldeka元のvibun画面に近い、テンポよく自動送り）で見せる。

## 演出モード（4種、ghoul-rushと同じ構成）
- **デフォルト**：標準の当選告知
- **突撃**：当たりの変動シーケンス中、以下5箇所を順にチェックし、最初に20%を引いた箇所で1回だけ「手落下！」カットインを挟む（以降は判定しない。通算的中率 約67%）
  1. ポケット投入直後
  2. スピン開始直後
  3. あおり突入時
  4. リーチ確定演出開始時
  5. リーチ中（テンパイ保持の中間）
- **リゼ襲来**：①ポケット投入の時点で、この変動が当たりだと確定していればrize画像を一瞬先読み表示（保留キューがないため「キュー生成時」ではなく「投入時」に読み替え）
- **月山絶叫**：リーチ中に予告ボタンを表示、押すと色抽選（白/点滅/青/緑/赤/虹、ghoul-rushと同じ重み付けの考え方をP_RUSH=1/7.7ベースで再計算）で確信度を示す

## 除外項目
- ST消化速度セレクター（自動ループしないため不要）
- 「終了する」スキップボタン
- 保留アイコン・保留キューUI

## Why
ユーザーが「超デカ版」でも同じRUSH演出特化コンセプトを踏襲したいが、ghouldekaには保留キューがないため、「貯めるボタン→ポケット投入→変動」という新方式で読み替えた。上乗せの仕組みも、ユーザーの要望で「当たれば必ず50%チャレンジ、成功する限り3000刻みで無限に伸びる」というシンプルな形に変更している（現行ghouldekaの6000/3000二択とは異なる、本プロジェクト独自のルール）。
